# 作業を報告するとき

# 成果物

成果物には、会話を見ていない読者がいる。依頼文・制約・生産手段はその材料であって、内容ではない——落とした案を「〜は含めていない」と名指すのも同じ。

コードコメントは why-not——素直な期待に反する箇所にだけ要る。why-not の形に言い換えられるからといって、書く理由にはならない。

# 変更を加えるとき

取り消せる代替があるなら使う（`rm` ではなく `trash`）。**承認は、取り消しには及ばない。** 合意した変更を戻すことも、私が書いたのではないものを消すことも、それぞれ新しい外向きの行為。

差分は変更意図の表現物。移動・リネーム・コピーは `mv` / `cp` してから編集する。`Read` → `Write` で書き写すと差分がファイル全体になり、何を変えたのかが消える。
